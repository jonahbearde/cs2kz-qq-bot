# 03: 决策核心——Send Window、Rotation、Tip List 生命周期与韧性

**What to build:** 机器人成为完整产品：在 Send Window（默认 09:00–24:00，北京时间，可配置）内按间隔（默认 30 分钟）逐条发送 Tip，时刻对齐墙钟间隔边界，窗口中途启动等待下一对齐时刻，宕机错过的不补发。Rotation 为持久化洗牌袋：一轮内不重复、发完重新洗牌、Tip List 增删后重新洗牌、重启续发、状态损坏自动重建。Tip List 文件变更即热加载；空/缺失列表静默跳过并记警告；发送失败 30 秒重试一次后跳过；日志带轮转。全部决策行为在单一测试缝（注入时钟 + 注入发送器 + 真实临时文件）上以 pytest 覆盖。

**Blocked by:** 02（曳光弹——发送链路已证明，核心逻辑接入真实发送）

**Status:** ready-for-agent

- [ ] 单一测试缝：调度/轮播/生命周期/韧性行为全部用 fake clock + fake sender + 真实临时文件测试，只断言"什么时刻发了什么"的外部行为；pytest 全绿
- [ ] 窗口边界：09:00 前沉默、首条 09:00、30 分钟间隔下末条 23:30、24:00 起沉默；时区固定 Asia/Shanghai，与服务器时区无关
- [ ] 时刻对齐间隔边界（30 分钟即 :00/:30）；窗口中途启动不立即发、等下一对齐时刻；长时间间隔后无补发突发
- [ ] 洗牌袋：一轮内全覆盖且无重复，发完重新洗牌；顺序+游标持久化，重启续发；状态文件损坏时干净重建
- [ ] Tip List 增删改无需重启即热加载并触发重新洗牌；被删除的 Tip 不再出现
- [ ] Tip List 为空或文件缺失：跳过发送、记警告、进程继续运行
- [ ] 发送失败约 30 秒后重试一次，再失败跳过等下一时刻；错误入日志；日志文件轮转
- [ ] 发送间隔与 Send Window 起止可经 .env 配置，无需改代码
- [ ] 测试群短间隔实测：对齐时刻发送、热加载生效、重启续发均可见（人工检查点）
